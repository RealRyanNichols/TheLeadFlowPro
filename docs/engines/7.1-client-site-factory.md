# Engine 7.1: Client site factory

Status: built on a branch, demo with fictional data, not sold or launched.
Pricing and go-live are decisions 23 to 25 in `docs/decisions-needed.md`.

## What it is

One JSON file per client turns into a five-page site: Home, Services, About,
Contact, and one conversion page (a quote, booking, estimate, or campaign
page). Every word, colour, phone number, and link on the site comes from
that file. The template names no business, price, or contact by hand, and a
QA script refuses any config that makes a claim the guardrails ban.

The site ships as its own small Next.js app to a Vercel project in the
client's account. Leads go where the client's config says: their inbox
through their own Resend key, their CRM webhook, or their LeadFlow plugin
inbound door. Nothing is stored on the factory side and nothing is copied
to The LeadFlow Pro.

## Files

| Path | Role |
| --- | --- |
| `factory/template/lib/config.ts` | `ClientConfig` type, `validateClientConfig`, routes, CTA resolution. No imports. |
| `factory/template/lib/schema.ts` | LocalBusiness and WebPage JSON-LD from the config. |
| `factory/template/lib/load.ts` | Reads and validates `site.config.json` inside the shipped app. |
| `factory/template/components/Site.tsx` | The frame and five page templates. Plain anchors and a plain HTML form, so the same code renders in the shipped app and in the admin preview. |
| `factory/template/styles/site.css` | One stylesheet; brand tokens arrive as CSS variables. |
| `factory/template/app/**` | The standalone app: layout, five routes, sitemap, robots, and `api/lead`. |
| `factory/clients/*.json` | Client configs. Only fictional fixtures are committed today. |
| `scripts/new-client.ts` | `npm run factory:new` copies the template to `build/clients/<slug>` (gitignored) and writes the config. |
| `scripts/qa-client-site.ts` | `npm run factory:qa` validates, renders, and checks a config. Exit 1 means do not launch. |
| `app/factory/preview/[client]/[[...page]]/page.tsx` | Admin-only, noindex preview of any committed config. Form disabled. |
| `tests/factory.test.ts` | Validation, structured data, preview isolation, scaffold, secrets, banned copy. |

## Setup (one time)

Nothing. The factory uses the repo's existing Node and Next install. The
shipped app declares its own dependencies in `factory/template/package.json`.

## Runbook: a new client site

1. **Scope.** Fill the intake on `/agency/start` or `/free-build`. Agree the
   five pages, the one conversion page, and where leads go. Write the
   `scopeApprovedOn` date into the config once the client agrees in writing.
2. **Config.** Copy `factory/clients/fixture-fence-co.json` to
   `factory/clients/<slug>.json` and replace every value. Keep
   `launch.status` at `draft`. Do not commit a real client's config to this
   public-facing repo without checking that nothing in it is private.
3. **QA.** `npm run factory:qa -- --config factory/clients/<slug>.json`.
   Fix every FAIL. The checks are listed below.
4. **Preview.** Sign in as admin and open
   `/factory/preview/<slug>` on a Vercel preview deployment. Walk all five
   pages on a phone. The banner says it is a preview and the form button is
   disabled.
5. **Scaffold.** `npm run factory:new -- --config factory/clients/<slug>.json`.
   The app lands in `build/clients/<slug>`, outside git.
6. **Client accounts.** The client creates (or already has) a Vercel account
   and a Resend account with their domain verified. They add Ryan as a
   collaborator on the Vercel project only if they want ongoing edits
   (hosting offer). They set the three env names from `.env.example` in
   their Vercel project themselves, or Ryan does it on a screen share.
   Never paste a client's key into this repo, a doc, or a chat.
7. **Deploy to the client's Vercel.** From `build/clients/<slug>`:
   `npm install`, `npm run build`, then `vercel --prod` while logged into
   the client's Vercel account, or connect the client's own GitHub repo.
   The domain is connected in the client's Vercel project, at their DNS.
8. **Launch.** Set `launch.status` to `live`, fill `domain`,
   `vercelProject`, and `scopeApprovedOn`, run QA again, redeploy. Until
   `live`, the site sends `noindex` and the sitemap is empty.
9. **Test the door.** Submit the form once with a test name. Confirm the
   client's inbox (or CRM) received it and the thank-you state rendered.
   Then delete the test lead on the client's side.
10. **Hand off.** Send the client the one-page summary: what each page
    does, where leads land, who answers them (`leadRoute.owner`), and how
    to request an edit.

## Launch checklist

- [ ] `npm run factory:qa` passes on the final config.
- [ ] Five pages checked on a phone and a laptop.
- [ ] Phone, email, and hours confirmed by the client in writing.
- [ ] Service area confirmed; street shown only if `showStreet` is true.
- [ ] Lead route tested end to end on the client's account.
- [ ] Consent line under the form reviewed by the client.
- [ ] GA4 or Meta Pixel IDs, if any, belong to the client's accounts.
- [ ] Domain connected at the client's DNS; HTTPS active.
- [ ] `launch.status` is `live` with `scopeApprovedOn` filled.
- [ ] Client has the Vercel project and the Resend account in their name.

## What QA checks

Config validity (every required field, E.164 phone, hex colours, https
URLs, a contact field on the form, no banned words in the conversion copy),
internal links resolve to the five routes, structured data names the
client and hides the street unless allowed, JSON-LD on every page, the
form has its honeypot and consent line, all fields render, analytics hooks
are present, no banned copy anywhere on the site (guarantee, #1, best in,
lowest price, ranked, top rated, ROI, ROAS), no LeadFlow Pro contact
details leaked, one H1 per page, contact page matches the config, and a
live status has its launch fields.

## Limits

- Five pages only. A sixth page is a custom build, not a config change.
- No CMS. Edits are config edits and a redeploy (the hosting offer with two
  edits a month covers this).
- No image pipeline. A logo is a path under `public/` or an absolute URL
  the client hosts.
- No blog, no e-commerce, no booking calendar. A booking CTA links out to
  the client's scheduler.
- The lead route sends one message. Retries and a failure queue belong to
  the LeadFlow plugin (`leadRoute.kind = leadflow_hq`), not the template.
- The template does not send SMS. The consent line exists so the client
  may call or text back; marketing texts need consent captured in the
  client's own system.
- First-party analytics means the `data-analytics` hooks on CTAs and the
  form. Wiring them to GA4 events is a follow-up once a client has GA4.
- The admin preview renders committed configs only. It never renders a
  config from a query string or a request body.

## Data and isolation

- Each client site is a separate app in the client's own Vercel project.
  No shared database, no shared analytics, no shared audiences.
- The factory keeps only the config file. It never stores a lead.
- The preview route is admin-only, `noindex`, `no-referrer`, and hides the
  site chrome. Its form is disabled and posts to itself, which is a page,
  not a handler.
- `build/` is gitignored so a scaffolded client app is never committed.

## Rollback

A client site is rolled back in the client's Vercel project (promote the
previous deployment). The factory itself is a set of files on this repo;
reverting the merge removes the preview route and scripts with no data
migration.
