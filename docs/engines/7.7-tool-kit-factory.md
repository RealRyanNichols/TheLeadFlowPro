# Engine 7.7: Tool and kit factory

Status: built on a branch on top of the existing tool registry. No new
tool is published by this engine; it ships the pipeline, the backlog, and
the one call to action every tool page now carries. Decisions 38 and 39
in `docs/decisions-needed.md`.

## What it is

A repeatable path from an idea to a published free tool or a $10 to $29
Pro Kit:

1. **Backlog** (`content/tools/backlog.json`): ideas aimed at East Texas
   business pains, each with the audience, the tool type, the lane its
   page should end on, where its numbers come from, and an approval
   record. Ryan approves an item by setting `status: "approved"` with
   `approvedBy` and `approvedOn`. Nothing else is scaffolded.
2. **Spec** (`content/tools/specs/<slug>.json`, from `TEMPLATE.json`):
   the page copy, taxonomy, fields, and formula source.
3. **Scaffold** (`npm run tool:new -- --spec …`): validates the spec
   against the taxonomy and the backlog approval, writes the tool file
   with `status: "proposed"`, and wires it into the registry. A proposed
   tool is not routable, not in the sitemap, not in search.
4. **Build**: write `run()`, the known-value test, the formula source
   entry, and the artwork. `npm run validate:tools` gates the build.
5. **Publish**: Ryan reviews the copy; `status: "published"`; the backlog
   item is marked published. The page appears in `/tools` from the
   registry, with the capture form (email the result, with consent boxes),
   the analytics events (`tool_started`, result copied, downloaded,
   printed, emailed, embed requested), and the one CTA.

## The one CTA

Every tool page ends on `FinalCta` fed by `lib/tools/cta.ts`. Two lanes:
`free_build` (the front door, default) and `agency`. A tool picks its lane
with `cta` in its metadata; validation refuses anything else. Before this
engine every tool ended on the `/start` mapper; now every tool ends on a
door into work.

## Runbook: a new tool

1. Add or pick a backlog item. Write the pain in one honest sentence.
2. Ryan sets `status: "approved"`, `approvedBy`, `approvedOn`.
3. Copy `TEMPLATE.json` to `content/tools/specs/<slug>.json` and fill it.
4. `npm run tool:new -- --spec content/tools/specs/<slug>.json`.
5. Write `run()` and the known-value test. Record the formula source.
6. `npm run art`, `npm run validate:tools`, `npm test`.
7. Ryan reviews the page on a preview deployment.
8. Set `status: "published"` in the tool file and `published` in the
   backlog. Merge. The page, the directory card, the sitemap entry, and the
   OG image follow from the registry.

A Pro Kit follows the same path with a `pro` block in the spec; its price
must be one of `PRO_PRICES`, and it must name the published free tools it
upgrades.

## Limits

- The scaffold writes copy and fields. It never writes a formula; a
  calculator without a verified expected output is not finished.
- The scaffold never sets `published`.
- Artwork briefs on scaffolded kits are TODO placeholders until written.
- The backlog is a file, not a database. Approval is an edit, which is
  the point: it is reviewed in a pull request.

## Rollback

Revert the merge. The eighty-six published tools are unchanged except for
the lane their final CTA opens.
