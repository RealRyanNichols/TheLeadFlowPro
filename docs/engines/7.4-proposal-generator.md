# Engine 7.4: Proposal generator

Status: built on a branch. Admin-only review page, two fictional samples,
no sending. Pricing source and go-live are decisions 32 and 33 in
`docs/decisions-needed.md`.

## What it is

Intake answers from `/start` (the guided router) or `/agency/start` (the
agency intake) become a scoped written proposal: the client's problem in
their own words, the recommended offer, modules, deliverables, what the
client owns, vendor costs disclosed, the price from the offers registry,
and the acceptance step. Ryan opens it from the lead, reads it, prints it
to PDF or copies the text, and sends it himself. The page never sends.

## Files

| Path | Role |
| --- | --- |
| `lib/proposals/build.ts` | `buildProposal(intake, now)`: interest or package → offer id, deliverables from the registry, ownership and vendor costs, price from `lib/site/offers.ts`, acceptance steps, and the `missing` list. `proposalText`. |
| `lib/proposals/render.ts` | Branded, print-ready HTML with every person-supplied string escaped. |
| `lib/proposals/fixtures.ts` | Two fictional intakes: a Company OS build and a two-service agency request. |
| `app/admin/proposals/[leadId]/page.tsx` | Admin review page. `sample-build` and `sample-agency` render the fixtures; a lead id renders that lead. Iframe preview, copy text, back to lead. |
| `app/admin/leads/[id]/page.tsx` | "Draft proposal from this intake" link. |
| `scripts/proposal-demo.ts` | `npm run proposal:demo` prints both samples and writes their HTML to `build/proposals/` (gitignored). |
| `tests/proposals.test.ts` | Price only from the registry, no invented scope, verbatim quote, missing flags, interest mapping, acceptance, copy rules, HTML escaping, no send path. |

## Where each part of the proposal comes from

| Section | Source | Never |
| --- | --- | --- |
| What you told us | `leads.goals` verbatim; `diagnostic.labels` (the router's own labels); budget bucket labels | Paraphrase into a claim |
| Recommended | `diagnostic.recommendation.package`, else `leads.interest`, mapped by `offerIdForInterest`; agency: `diagnostic.services` | An offer not in the registry |
| Modules | `diagnostic.recommendation.modules` with its `module_labels`, else `leads.desired_modules` | Modules the client did not pick |
| Deliverables | The offer's `terms`; each agency service's `included` list; the module labels | Free text |
| What you own | Agency: service `clientOwns` plus the ownership promise. Builds: code, domain, hosting, records, accounts | Nothing implied |
| Vendor costs | Agency: `clientPaysDirectly`. Builds: hosting offers from `PRICES`, domain and subscriptions | Estimates |
| Price | `offer.priceLabel` and `offer.terms` | A number typed here |
| To accept | Reply Approved or sign; deposit link only when the offer has a Stripe link; kickoff within five business days | Auto-send |

An offer with status `tbd_ryan` prints the neutral TBD line and adds a
"fix before sending" item. A larger build (Company OS, Custom Platform,
Lead Engine, Training Platform) always includes the System Map first,
because the System Map's own terms say it is credited toward the build.

## Runbook

1. Open the lead in `/admin/leads/<id>` and click "Draft proposal from
   this intake".
2. Read the "Fix before sending" list. A TBD price means set the number
   (in the registry, or on the call) before anything goes out.
3. Print the frame to PDF (the fix list and sample banner do not print),
   or copy the text into an email.
4. Send it yourself from hello@. Record the send as a note on the lead.
5. Acceptance: the client replies Approved or signs. For Website Launch
   the deposit link is in the proposal; for everything else send the
   invoice after approval.

## Limits

- One recommended offer per build intake (plus the System Map where it
  applies). Bundles are written by hand.
- Module labels fall back to a humanized id when the intake did not carry
  labels (older diagnostics).
- No stored proposal versions yet. The page rebuilds from the lead each
  time; a sent copy is the PDF or the email.
- No e-signature. Acceptance is a reply or a signed agreement outside the
  app.
- The agency "websites" service maps to Website Launch and prints its
  price; the free five-page program is a separate offer and is not
  proposed from the agency intake.

## Rollback

Revert the merge. No data, no migration, no accounts.
