# Engine 7.5: Workshop kit

Status: built on a branch. The September 17 workshop now renders from its
kit with no copy change; the next event is a config entry plus a copy
review. Go-live notes are decision 34 in `docs/decisions-needed.md`.

## What it is

Everything a live workshop needs, keyed by event slug: the registration
page copy, the private paid-attendee page's prep checklist, a printable
worksheet, and the three-step follow-up sequence with the event's own
date, recap, and day-2 offer. Date, price, seat count, and address stay on
the database event row and the SITE_EVENTS entry, so no kit copy can go
stale.

## Files

| Path | Role |
| --- | --- |
| `lib/site/workshopKit.ts` | `WorkshopKit` type, `WORKSHOP_KITS`, `KIT_TEMPLATE` to copy, `kitCopyProblems`, `DAY_TWO_OFFERS`, `worksheetPath`. |
| `lib/site/events.ts` | Unchanged: the SITE_EVENTS entry with date, seats, price, artwork, status. |
| `app/events/[slug]/page.tsx` | Registration page. Metadata, eyebrow, intro, includes, bring line, and details link from the kit. Any published database event renders with default copy. |
| `app/events/[slug]/confirmed/**` | Paid-attendee page. Prep checklist and worksheet link from the kit; no attendee data in either. |
| `app/events/[slug]/worksheet/page.tsx` | Printable worksheet from the kit. Unlisted, noindex, 404 without a kit. |
| `lib/workshopFollowUp.ts` | `buildWorkshopFollowUp(event, kit)`; the featured event's sequence keeps its original exports. Drafts only, not activated. |
| `scripts/check-workshop.ts` | `npm run workshop:check -- --slug <slug>`: config complete, copy clean, follow-up renders, plus the database fields to confirm. |
| `tests/workshop-kit.test.ts` | Kit completeness, copy rules, page wiring, worksheet, per-event follow-up, the check. |

## Runbook: the next workshop

1. **SITE_EVENTS.** Add an entry in `lib/site/events.ts`: slug, title,
   kicker, `startsAt` with the Central offset, durations, seats, price
   from `PRICES`, artwork under `public/images/workshops/`, `status: "auto"`.
   Set the previous event's `nextEventRef` to the new slug so its past
   state advertises the new date.
2. **Kit.** Copy `KIT_TEMPLATE` in `lib/site/workshopKit.ts` into a new
   constant, replace every string, add it to `WORKSHOP_KITS`. No dates,
   prices, times, or seat counts in kit copy; the check refuses them.
3. **Catalog.** Add `/events/<slug>` and `/events/<slug>/worksheet` to
   `lib/publicPageCatalog.ts` with `index: false`.
4. **Check.** `npm run workshop:check -- --slug <slug>` until every line
   is PASS. It prints the database fields to confirm next.
5. **Database row.** In `/admin/events` create the row: slug, start,
   price, capacity, address and visibility, arrival notes, policies.
   `date_confirmed` and `is_published` stay false until Ryan locks the
   date. Registration opens only when both are true and payment config is
   present (unchanged logic).
6. **Copy review.** Read the registration page, the worksheet page, and
   the three follow-up drafts (`WORKSHOP_FOLLOW_UP_STEPS` render with a
   fixture context in the test) with Ryan's voice in mind.
7. **Stripe.** Nothing to create: checkout sessions are created server
   side per event from the row's price. The Website Launch deposit link is
   the only hosted link and is unrelated.
8. **Announce.** Publish the row. The homepage banner, hero, calendar,
   and /events read the event through the existing featured-event state.
9. **After the room closes.** Mark attendees `attended` in `/admin/events`.
   The follow-up drafts are ready to send by hand; activating them as an
   automation is a separate approval (decision 34).

## What did not change

- Registration, seat claims, Stripe checkout, confirmation email, the
  calendar file, and the attendee API are untouched.
- The September 17 registration page and follow-up copy render exactly as
  before; the strings moved into the kit.
- The past-state swap (auto at 8:30 PM Central) is unchanged.

## Limits

- One kit per event slug. Two events sharing a kit means two entries.
- The worksheet is a printed page, not a fillable PDF.
- The long-form marketing content on `/events` (`workshopContent` in
  `lib/events.ts`) is still keyed to the founding workshop; a second
  marketed-in-full event needs its own `WorkshopContent` entry there.
- The follow-up remains a draft. Sending is by hand until activated.

## Rollback

Revert the merge. No data, no migration, no accounts.
